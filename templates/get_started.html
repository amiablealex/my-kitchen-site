Get started

Up and running

My Kitchen runs on your own hardware. If you use Home Assistant, the add-on is the simplest path — install, updates and secure remote access are handled for you. Plain Docker works just as well if you'd rather not.

{{ icon('home') }} Home Assistant add-on

The recommended path if you run Home Assistant OS — for example on a Raspberry Pi. It installs, updates and reaches My Kitchen securely, including from your phone via the companion app.

  1. Add the repository. In Home Assistant go to Settings → Add-ons → Add-on store, open the ⋮ menu (top right), choose Repositories, paste the URL below and click Add. 
    {{ site.ha_repo }}
  2. Install. Close the dialog, find My Kitchen in the store and click Install. The first build clones the app and may take a few minutes.
  3. Configure. On the Configuration tab, set your LLM provider and API key (see Configuration below). Save.
  4. Start. On the Info tab, click Start. Turn on Show in sidebar for one-tap access.
  5. First login. Open the add-on. A starter account is created automatically and its password is printed once in the add-on Log tab — log in, then change it under Household.
{{ icon('info') }}
Remote access. With Home Assistant Cloud (Nabu Casa) or your own HTTPS, the add-on is reachable securely through HA ingress — no ports to forward and nothing exposed directly to the internet.

{{ icon('dns') }} Docker

Prefer to run it standalone? My Kitchen is a single container with a single-file SQLite database on a mounted volume, and it runs database migrations automatically on start.

  1. Clone the repo. 
    git clone {{ site.github }}.git
cd my-kitchen
  2. Set your config. Copy the example environment file and fill in your values — at minimum a stable SECRET_KEY, your LLM provider and API key, and the database path. The repository's DEPLOY.md lists every variable. 
    # a few of the key variables (see DEPLOY.md for the full list)
SECRET_KEY=change-me-to-a-long-random-string
MY_KITCHEN_DB_PATH=/data/my_kitchen.db
LLM_PROVIDER=gemini
APP_TIMEZONE=Europe/London
  3. Launch. 
    docker compose up -d --build
  4. Reverse proxy (optional). Put it behind nginx or Caddy for a clean hostname and TLS, exactly as you would any small web service.

Configuration

My Kitchen talks to a large language model through a swappable provider adapter. Set these in the add-on's Configuration tab, or as environment variables under Docker.

SettingWhat it doesDefault
LLM providerWhich model service to use: gemini, anthropic, or mock (no API calls — for trying the app).gemini
API keyYour key for the chosen provider. Stored on your device; sent only with generation requests.—
ModelThe specific model to call.gemini-3.5-flash
TemperatureHow adventurous generation is. Higher = more variety.0.8
Max tokensOutput length ceiling per generation.8000
TimezoneUsed for recipe history timestamps.Europe/London

Fully local? The provider adapter is designed to accept a local model (e.g. Ollama) too. A Raspberry Pi won't match a hosted model's quality and speed today, but if you have the hardware, a fully on-network setup is on the table. See Privacy & data.

Updating & backups

Home Assistant: new versions appear on the add-on's update screen — click Update. Database migrations run automatically. Configure Settings → System → Backups so HA snapshots the add-on before schema-changing releases.

Docker: git pull then docker compose up -d --build; migrations apply on start. Your data lives on the mounted /data volume — back that up on your normal schedule.
