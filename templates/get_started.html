Get started

Three ways to install it, the settings you'll need, and what to do first.

{{ icon('home') }} Home Assistant app

The simplest option if you already run Home Assistant. It installs from a repository, updates through Home Assistant, and is reachable remotely through Home Assistant's own login.

{{ icon('info') }}
Apps (previously called add-ons) need Home Assistant OS or Supervised. On Container or Core, use Docker instead.
  1. Add the repository. Go to Settings → Apps → Install app, open the ⋮ menu, choose Repositories, paste this URL and click Add. 
    {{ site.ha_repo }}
  2. Install. Find My Kitchen in the list and click Install. The first install builds the image locally, which takes a few minutes on a Raspberry Pi.
  3. Configure. On the Configuration tab, choose a provider and add its API key (see Configuration). Save.
  4. Start. On the Info tab, click Start, and turn on Show in sidebar if you want it there.
  5. Log in. A first account is created on the first start, and its password is printed once in the Log tab. Log in with it, then change it under Household.

With Home Assistant Cloud or your own HTTPS setup, the app is reached through Home Assistant's ingress, so there are no ports to forward.

{{ icon('dns') }} Docker

One container, with the SQLite database on a mounted volume. Database migrations run automatically when it starts.

  1. Clone the repository. 
    git clone {{ site.github }}.git
cd my-kitchen
  2. Set the configuration. Copy the example environment file and fill it in. At minimum you need a SECRET_KEY, a provider and its API key, and the database path. DEPLOY.md lists every variable. 
    # the main ones; DEPLOY.md has the full list
SECRET_KEY=change-me-to-a-long-random-string
MY_KITCHEN_DB_PATH=/data/my_kitchen.db
LLM_PROVIDER=gemini
GEMINI_API_KEY=...
APP_TIMEZONE=Europe/London
  3. Start it. 
    docker compose up -d --build
  4. Reverse proxy (optional). Put it behind nginx or Caddy if you want a hostname and TLS.

{{ icon('tune') }} Plain Python

It's an ordinary Flask app, so you can run it without a container.

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # then edit it
flask db upgrade && flask seed  # database + starter ingredients
python run.py

With LLM_PROVIDER=mock no API key is needed, which is a quick way to look around before adding one.

Costs and limits

The app is free. AI calls are billed to your own API key: new recipes, new versions, retries, @kitchen questions, receipt reads, list matches and imports. Stock, suggestions, browsing and everything else run locally. In my house it comes to pennies a month, but it's worth setting a spending cap with your provider as well.

Daily limits stop a busy evening (or a bug) running up a bill. They reset at midnight, and the Usage page shows where you are against them and what's been spent.

First steps

About a quarter of an hour here makes the difference between an empty app and a useful one.

  1. Change the starter password and add everyone else in the house, under Household.
  2. Add dietary tags (allergies, dislikes, diets) and assign them to people. A tag that isn't assigned to anyone never reaches a brief.
  3. Trim the ingredient catalogue. A new install starts with about 170 common ingredients. Under Manage → Ingredients, retire the ones you never buy and add the ones you do. Everything else builds on this, so it's worth doing properly.
  4. Check the staples. Anything you always have (oil, salt, common spices, flour) should be a staple, so it stays off the stock list and can always be used.
  5. Add your equipment under Manage, so recipes are written for your kitchen.
  6. Set your stock with one pass through the fridge and cupboards. Typing it as a list (“milk, eggs, leeks, …”) into the stock search adds it in one go, and after a shop, the receipt icon does the same from a photo.
  7. Add a few recipes you already make. Recipes → Add a recipe: import them from a link or a photo of the book, or write them in. Suggestions are empty until you have some.
  8. Cook something. Tap Lets Cook.

Updates and backups

Home Assistant: new versions appear with your other updates. If you want a snapshot before each update, turn that on under Settings → System → Backups.

Docker: git pull, then docker compose up -d --build. Migrations run on start. Your data is on the mounted /data volume, so back that up however you normally would.

Each version's changes are on the Releases page.
