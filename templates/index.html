{{ site.name }}

A recipe app for one household, self-hosted and open source.

I built it for my own kitchen. It keeps track of what's in stock, holds the recipes we cook, and shows which of them we can make with what's in. When none of them fit, it asks an AI model for two new ones. Recipes can also be written in, imported from a web page or read from a photo of a cookbook.

Get started {{ icon('arrow_forward') }} {{ icon('menu_book') }} Docs Source on GitHub
Runs on
Home Assistant (as an add-on), Docker, or plain Python.
Built with
Flask, SQLite and server-rendered templates. No JavaScript framework and no build step.
AI
Google Gemini or Anthropic, with your own API key, or (untested) your own model through an OpenAI-compatible server such as Ollama. Used to write and revise recipes, answer questions, read receipts and lay out imported recipes; everything else runs locally. A mock provider lets you try it without a key.
Cost
Free, MIT licence. API use is billed to your key: pennies a month for a household, under daily limits you set.

Features

  • {{ icon('shelves') }}

    Stock

    Each ingredient is either in or out, grouped by section, with an optional note such as “needs using”. Staples like oil and spices are assumed and kept off the list. Paste a shopping list to add several at once, and mark what a recipe used up when you've cooked it.

  • {{ icon('menu_book') }}

    Recipes

    Generated recipes, ones you write yourself and imported ones sit in one list. Ingredient lines are linked to your ingredient catalogue, which is what lets the app check a recipe against your stock.

  • {{ icon('photo_camera') }}

    Importing recipes

    Paste a link to a recipe, paste its text, or photograph a cookbook page or a handwritten card, over several pages if it runs on. It comes in with its own wording, laid out like the rest, for you to check before saving.

  • {{ icon('receipt') }}

    Receipts

    Photograph a shopping receipt, frame just the item lines, and the app offers to mark what you bought as in stock. Only the framed part is sent, and lines it can't place are listed for you rather than dropped.

  • {{ icon('search') }}

    Cooking from what's in

    A short wizard asks what you want to use up, the meal, cuisine, time and who's eating, then lists the saved recipes you can make now. The home page says how many you could cook before you start. That part is a database query, with no AI involved.

  • New recipes

    If nothing fits, the brief goes to the model, which writes two different recipes to choose between. You can add a request, such as “something spicy”, or ask for two more.

  • {{ icon('edit') }}

    Versions

    Ask for a change (“make it for four”, “swap the broccoli for green beans”) and the app writes a new version. Earlier versions stay in a trail on the recipe, and nothing is sent until you confirm.

  • {{ icon('comment') }}

    Questions in the notes

    Start a note with @kitchen to ask about that recipe, and the reply arrives in the thread. If it suggests a bigger change, one tap turns it into a new version.

  • {{ icon('group') }}

    Household

    Each person has a login, favourites and dietary tags: allergies, dislikes and diets. Choose who's eating and their tags go into the brief.

  • {{ icon('lock') }}

    Your data

    Everything is stored in one SQLite file on your machine. Only what an AI request needs leaves your network, sent to your provider with your key, and photos are never kept. Privacy & data
